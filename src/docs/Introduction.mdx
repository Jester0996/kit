# a11y-ui-kit

Набор доступных React-компонентов на Radix UI. Цель проекта: соответствие WCAG 2.2 AA.

## Принципы

- Всё, что делается мышью, делается и с клавиатуры.
- Индикатор фокуса всегда виден и не теряется при смене состояний.
- Роли, имена и состояния задаются нативной семантикой, а ARIA добавляется только там, где её не хватает.
- Анимации отключаются при `prefers-reduced-motion: reduce`.

## Компоненты

- [Button](?path=/docs/components-button--docs): варианты, размеры, состояние загрузки и `aria-disabled`. Кнопка остаётся в порядке фокуса, но не реагирует на нажатия.
- [Dialog](?path=/docs/components-dialog--docs): модальное окно с заголовком и описанием. Фокус заперт внутри, после закрытия возвращается на кнопку открытия.
- [Tabs](?path=/docs/components-tabs--docs): вкладки по шаблону WAI-ARIA. В порядке табуляции только активная вкладка, у списка обязательно есть доступное имя.
- [Tooltip](?path=/docs/components-tooltip--docs): подсказка по фокусу и наведению. Закрывается по `Esc`, не исчезает под курсором и описывает триггер через `aria-describedby`.
- [TextField](?path=/docs/components-textfield--docs): поле ввода с обязательной подписью, подсказкой и озвучиваемой ошибкой.

## Как проверяется поведение

- Каждая история проходит проверку axe через аддон доступности. Нарушения роняют тест (`a11y.test: "error"`).
- `play`-функции повторяют действия пользователя: `Tab`, стрелки, `Home`, `End`, `Enter`, `Esc`, наведение и ввод текста.
- Unit-тесты на Testing Library проверяют роли, доступные имена и связи через `aria-describedby`.

## Что нужно знать

- Подсказка не открывается на тач-экране, поэтому нужное для работы в неё не кладётся. Если кнопка недоступна, причину лучше показать и текстом рядом.
- Недоступную кнопку, чьё состояние нужно объяснить, делайте через `aria-disabled`, а не `disabled`: только так она получает фокус и подсказка открывается с клавиатуры.
- Автоматические проверки не заменяют ручные. Проверка скринридером (NVDA) запланирована, результаты в проекте пока не записаны.
